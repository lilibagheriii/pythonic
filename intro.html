Learning Path Quickstart

You run your own learning. Two shortcuts do the bookkeeping, so you can spend your time writing code.

llearnKeeps your chapter logs: exercises, notes, questions, parked items
ssyncGets your mentor's feedback and submits your progress

Everything here happens in PyCharm, with commands typed in PyCharm's terminal. You install the shortcuts in step 5 below.

Once, on day one

The pythonic repo is already cloned and connected to GitHub. Do these once, in order.

  1. Install Python 3 and PyCharm (the free Community edition is enough)

    The book uses VS Code. We use PyCharm instead, so follow PyCharm's steps wherever the book shows VS Code.

  2. Open the pythonic folder in PyCharm (File → Open)
  3. Give the project its own virtual environment

    Settings (⌘, on Mac, Ctrl+Alt+S on Windows) → Project: pythonic → Python Interpreter → Add Interpreter → Add Local Interpreter → Virtualenv Environment → New. Set the location to the .venv folder inside pythonic, and the base interpreter to your Python 3. Then check that Tools → Terminal → Activate virtualenv is ticked. Python tools then install into the project, and the terminal picks them up by itself.

  4. Open the terminal (⌥F12 / Alt+F12) and install the tools (the prompt should start with (.venv)) 
    python -m pip install -r requirements.txt
  5. Install the shortcuts, then close the terminal and open it again (if a letter is taken, it tells you how to pick another) 
    $ bin/install-aliases
$ exit

    exit closes the terminal. Open it again with ⌥F12 (Mac) or Alt+F12 (Windows). The shortcuts only work in a terminal opened after installing. This is the only time you type a bin/ path. From now on, l and s work from any folder.

  6. Check the connection to GitHub (it should end with “✓ In sync.”) 
    s

    If it says you don't have access, ask your mentor to check your access to the repo on GitHub.

  7. Start your first session 
    l session pcc-00

On Windows: the scripts need Git Bash. Set Settings → Tools → Terminal → Shell path to Git Bash (usually C:\Program Files\Git\bin\bash.exe), then open a new terminal tab.

Every study session

The same loop, every time, starting with l session and the chapter you're working on. Steps 3 to 5 repeat for each exercise in the chapter. Same chapter as last time? Leave out the id: l session --hours 2.

  1. First thing: pick today's chapter and start its log entry 
    l session pcc-02 --hours 2
  2. Get your mentor's feedback and submit your progress 
    s
  3. Create a file for the next exercise (number and title from the book) 
    l ex 2-1 "Simple Message"

    Creates exercises/ex_2_1_simple_message.py and adds it to your log's checklist.

  4. Write the code, run it, fix it (run it with PyCharm's Run button)

    Type the book's examples out by hand. Copy-pasting skips the part where you learn.

  5. Tick it off when it works 
    l done 2-1
  6. Before you stop, open the chapter's LOG.md and fill in today's entry

    Did, Learned, Confusing, Next time. One line each is enough.

  7. Last thing: get feedback and submit your progress again 
    s

When something gets in the way

Stuck

Try for 30 minutes first. Then ask, and say what you tried, so your mentor can see where it went wrong.

l ask "Why does 0.1 + 0.2 print 0.30000000000000004? Tried round()"

Need to move on

Park it so it isn't forgotten, keep going, and come back later. l parked lists everything you've parked.

l park "2-8: redo after reading about string methods"

Learned something

Write it down while it's fresh: a gotcha, an aha moment, a useful link.

l note "f-strings need the f before the quote"

Close them later with l unpark 1 and l answered 1 "what I learned". The number comes from l parked or l questions.

Finishing a chapter

  1. Fill in the Retro at the bottom of the chapter's LOG.md

    What clicked, what's still fuzzy, and how you'd explain the main idea to a beginner.

  2. Mark it complete 
    l complete

    If exercises, parked items or the retro are unfinished, it lists them and stops. Finish them, or agree with your mentor to move on and use l complete --force.

  3. Pick the chapter it suggests at the start of your next session 
    l session pcc-03

What goes where in LOG.md

A chapter's folder and LOG.md appear the first time you pick it with l session <id> (or l start <id>). The log is created from templates/LOG.md as it is at that moment, so your mentor can change the format as you go. The commands write into these sections for you, and you can edit any of them by hand. If a section is missing, the commands add it when they need it.

**Status:** in-progressWhere the chapter standsl start · l complete
## GoalsWhat you should be able to do at the endyou
## ExercisesA checklist that links to each exercise filel ex · l done
## Session logOne dated entry per study sessionl session
## RemarksGotchas, aha moments, linksl note
## Questions for mentorOpen questions, then the answersl ask · l answered
## ParkedUnfinished things to come back tol park · l unpark
## Mentor feedbackWritten by your mentor; arrives with smentor
## RetroYour look back before completingyou

Working on something beside your chapter

Some logs run alongside the books, such as job search and algorithm practice. Add -c and the log's id to use any command on another log without switching.

$ l ex 1 "Two Sum" -c add-algorithms
$ l note "Applied: junior developer role, via referral" -c add-job-search

If s stops with a conflict

That means you and your mentor changed the same lines of a code file. Nothing is lost, because s puts everything back the way it was and names the file. Run s --keep-mine to keep your version of those lines, or ask your mentor which one to keep. Edits to the same LOG.md never cause this. Both sets of lines are kept automatically.

All commands

Commands that change a log use your current chapter unless you add -c <id>. Ids work without leading zeros, so pcc-3 finds pcc-03.
